# Mars Pathfinder AI

火星智能探测与路线规划系统（Mars Pathfinder AI）是 OrionX 面向 NASA Space Apps Challenge 2026 开发的研究与演示型原型。

项目以 Jezero Crater（耶泽罗陨击坑）为主要研究区域，结合火星地形、天气与环境、漫游车能源状态以及科学兴趣点，为未来火星探测任务生成并比较候选路线。

本项目的目标是展示一个**可解释、可验证、可扩展**的火星任务规划系统，而不是飞行级或实际部署的导航系统。所有真实观测数据都必须标注来源、分辨率、坐标系、单位和限制；合成数据只能用于算法测试，并明确标记为 synthetic。

## 项目目标

系统计划支持以下能力：

- 显示火星 DEM、轨道影像、坡度和地形风险图层；
- 读取并校验多种 NASA 或官方提供的科学数据；
- 根据起点、目标点和任务约束计算候选路线；
- 比较最短距离、最低能源消耗、最低风险和高科研价值路线；
- 综合考虑地形、天气、漫游车剩余能源和科学兴趣点；
- 展示路线距离、能源消耗、坡度、风险和科研价值等可解释指标；
- 在新的环境数据或漫游车状态到达后支持动态重新规划。

## 核心设计思路

项目采用“确定性规划引擎 + 多目标优化 + AI 任务助手 + 受控学习”的组合方案。

AI 不直接绕过安全约束决定路线。大模型（例如 DeepSeek）负责将自然语言任务转换为结构化参数、解释候选路线和生成任务报告；路线搜索、能源约束和不可通行区域检查由可测试的程序完成。

每个路径段的综合代价可以表示为：

```text
总成本 = 距离成本
       + 地形风险成本
       + 天气风险成本
       + 能源消耗成本
       - 科研价值收益
```

以下条件属于硬约束，而不是可随意牺牲的评分项：

- 剩余能源必须高于安全返航阈值；
- 坡度和地形条件必须满足漫游车能力限制；
- 极端天气或环境风险超过阈值时禁止通行；
- 缺失数据和不可通行区域必须被显式处理；
- 路线应满足任务所需的通信或中继条件（如果数据可用）。

系统可以输出多条 Pareto 候选路线，例如最短路线、最省能源路线、最安全路线、科研价值最高路线和综合平衡路线，而不是只返回一个无法解释的“最优答案”。

## 系统架构

```text
数据层
├── DEM / 坡度 / 障碍
├── 火星天气与环境
├── 漫游车状态与能源
└── 科研兴趣点

预测层
├── 每段路能源消耗估计
├── 天气风险估计
├── 地形通行风险估计
└── 科研价值评分

规划层
├── A* / Dijkstra
├── 多目标代价函数
├── 硬约束检查
└── 动态重新规划

AI 层
├── 自然语言任务解析
├── 目标权重和约束转换
├── 候选路线比较
└── 结果解释与报告生成

学习层
├── 根据历史行驶数据校准能耗模型
├── 根据实际环境修正风险模型
└── 保存模型版本和训练记录
```

推荐的数据流是：

```text
官方 / NASA 数据
    → 数据接入与验证
    → 统一 TerrainGrid / MissionState
    → 地形与风险分析
    → 加权图或代价网格
    → A* / Dijkstra / 多目标规划
    → 路线指标与科学目标评估
    → Streamlit + Plotly 可视化
```

真实数据和合成数据使用同一套接口。官方数据发布前，可以使用明确标注的合成 DEM 验证算法；接入真实数据时只替换数据适配层，不重新设计规划引擎。

## 技术栈

- **Python 3.11+**：主要开发语言；
- **NumPy / SciPy / Pandas**：数值计算和数据处理；
- **Rasterio / PyProj**：栅格数据和坐标处理；
- **NetworkX 或自定义搜索算法**：图结构和路径规划；
- **A* / Dijkstra**：最短路径和风险感知路径；
- **Streamlit / Plotly**：交互式应用和图表；
- **Pytest**：单元测试与算法验证；
- **DeepSeek 等模型 API（可选）**：任务解析、解释和报告生成，不负责绕过安全约束。

初期避免引入复杂 Agent 框架和不必要的机器学习服务，保持代码轻量、可测试、可在普通笔记本上运行。

## AI 与自学习路线

### 阶段一：确定性 MVP

先使用规则、代价函数和 A* / Dijkstra 实现可靠的路线规划。AI 不是 MVP 的硬依赖，系统在没有外部模型服务时也应能完整运行。

### 阶段二：接入 AI 助手

通过统一的 `AIProvider` 接口接入 DeepSeek 或其他模型。模型可以把如下任务：

> 优先考虑科研价值，但必须保留 25% 能源用于返航，并避开高风险天气。

转换为经过程序校验的结构化参数，然后由规划器计算路线。模型还可以解释路线差异、提示风险和生成任务报告。

### 阶段三：受控自学习

不在初期训练完整强化学习 Agent。真实火星行驶数据稀缺，且模拟环境与真实环境存在差异，更适合先根据遥测数据逐步校准：

- 预计能源消耗与实际能源消耗；
- 预计通过时间与实际通过时间；
- 预测地形或天气风险与实际观测；
- 不同载荷、温度和坡度对能耗的影响。

学习模块只更新能耗和风险模型的参数，并保存模型版本；硬约束、可通行性规则和最终路线检查仍由确定性程序负责。

## MVP 范围

第一版可运行原型需要完成：

1. 加载一份覆盖有限区域的真实 Mars DEM（官方数据未发布前使用标记清晰的合成数据）；
2. 显示高程图和坡度图；
3. 支持选择起点和目标点；
4. 计算最短路线和坡度感知路线；
5. 展示两条路线及高程剖面；
6. 比较距离、坡度、风险和能源指标；
7. 对数据来源、单位、坐标系和限制提供说明；
8. 为地形分析和路径规划提供可重复的测试。

## 开发阶段

1. **项目基础**：目录、依赖、数据模型、测试和元数据规范；
2. **地形处理**：DEM 加载、校验、裁剪、坡度和可通行性分析；
3. **路线引擎**：A*、Dijkstra、代价函数、硬约束和路线指标；
4. **交互界面**：Streamlit 地图、起终点选择、路线对比和高程剖面；
5. **多源数据**：天气、能源状态、科学兴趣点和数据溯源；
6. **AI 助手**：任务解析、路线解释和报告生成；
7. **验证与展示**：真实数据验证、异常情况测试、演示流程和限制说明。

## 数据与科学规范

- 不提交大型原始数据、密钥或个人凭据；
- 每个数据集必须登记来源、版本、空间范围、分辨率、坐标系、单位和限制；
- 不把模拟值描述为 NASA 实测数据；
- 明确区分观测数据、派生数据、预测数据和合成数据；
- 对缺失数据、分辨率差异和坐标变换保留处理记录；
- 所有路线结果都应展示输入数据和关键参数，保证结果可解释、可复现。

## 团队协作约定

推荐按模块使用独立分支协作：

- `data`：数据加载、验证和元数据；
- `terrain`：坡度、障碍和可通行性；
- `routing`：A*、Dijkstra 和代价函数；
- `analysis`：路线指标、多目标比较和能源模型；
- `ui`：Streamlit 和 Plotly 界面；
- `ai`：模型适配、任务解析和解释；
- `tests-docs`：测试、数据说明和演示文档。

模块之间优先通过稳定的数据模型和函数接口交汇，避免直接依赖其他模块的内部实现。

## 项目定位

Mars Pathfinder AI 是科学计算、路径规划和交互式任务分析的研究原型。它用于探索如何把多种火星数据转化为可解释的任务建议，不应被视为真实火星任务中的飞行级导航或安全系统。
