# Mars Pathfinder AI 技术审阅方案

2026 年 11 月 13 日 · Jezero Crater · Hawksbill Gap

## 1. 建议确认的作品范围

做一个**可离线运行的局部火星出舱任务规划网页**。两名宇航员从模拟基地出发，在 Jezero 西部三角洲 Hawksbill Gap 的两处科学目标附近比较沉积岩，然后返回。二维地图负责选路线和执行回放。同一份高程数据生成可旋转的三维地形，帮助解释陡坡、绕行和阴影。在线版给评委直接打开，现场用笔记本运行同一套应用和数据。规划、重规划、三维和回放均可在本地计算。

挑战要求把多个 NASA 科学任务的数据融入同一个局部位置或路线，为人类探索者提供规划、执行和开展科学工作的依据。题目建议整合至少三类数据，并允许使用历史场景。作品把 MRO HiRISE 数值地形与光学、Mars Odyssey THEMIS 热红外、Mars 2020 地面光学和大气观测放进同一个任务界面，并以 USGS 地质图解释站点。光学、地形和热红外三个类别使用现有真实裁片即可建立。官方 Resources 中的 Mars Trek 影像和毅力号原始影像直接进入作品。GO Team 要求争取 Global Awards 的作品至少使用该题 Resources 中的一项 NASA 数据，并在提交中列明全部数据、图像和工具。题意依据你贴出的 Details 和五条 Resources，官方挑战网页在本次公开抓取中未返回正文。 [挑战 Details](https://www.spaceappschallenge.org/2026/challenges/interplanetary-survival-guide-martian-map/?tab=details) · [官方 Resources](https://www.spaceappschallenge.org/2026/challenges/interplanetary-survival-guide-martian-map/?tab=resources) · [GO Team 答复](https://github.com/nasa/spaceapps/discussions/1827)

科学任务拟定为**比较不同沉积岩相与后期水蚀变线索**。Swift Run 位于 Skinner Ridge，关注砂岩的颗粒和层理。Hazeltop 位于 Wildcat Ridge，关注含硫酸盐的细粒沉积岩和脉体。站点卡给出观察清单、图片证据、优先级和预计停留时间。NASA 采样点、历史火星车轨迹、模拟宇航员观察站和模拟基地各有独立的图例。初始任务区约 520 × 520 m，沿用当前裁片。Sol 518 用作照片与历史环境回放的参考，两个样本的封存记录分别是 Sol 490 和 Sol 509。观察站与崖缘的间隔、能否看到露头，以及真实坐标的叠加精度需要验收后才能确定。 [NASA 岩石样本](https://science.nasa.gov/mission/mars-2020-perseverance/mars-rock-samples/) · [NASA 双露头标注图](https://science.nasa.gov/resource/two-perseverance-sampling-locations-in-jezeros-delta/) · [NASA PDS 采样报告](https://pds-geosciences.wustl.edu/missions/mars2020/Mars%202020%20Initial%20Reports%20Volume%202%20Release%202.pdf) · [任务区地层研究](https://doi.org/10.1029/2023JE008187)

## 2. 数据怎么获取和调用

**使用官方服务按区域、产品或 Sol 获取，运行时读取经核验的小包。** 全球与区域浏览可以按视野请求显示瓦片，步行计算读取裁好的数值栅格。精确工作流先查询覆盖，再读图像对应的 TIFF 数据块或矢量要素，最后缓存结果。现有高程、影像、地质、热红外、路线预览与两张照片合计约 **12.3 MB**。之前的约 52.4 MB 压缩包还包含完整采样报告、原始请求记录和参考素材。最终包大小取决于地平线分析缓冲区、光照时间片、图片和前端资源，首版以十几至几十 MB 为预算，运行环境单独计量。

```text
官方数据入口 ── 按范围或 Sol 取数 ── 投影、质检与本地缓存
                                             │
                                     版本固定的任务包
                            ┌────────────────┼────────────────┐
                        二维地图         多目标规划         三维预览
                            └────────────────┼────────────────┘
                                  任务回放、返航与导出
```

### 2.2 其余官方资源在成品里的位置

- **USGS–NASA 地质地图**出现在区域定位和科学站解释中。局部路线风险另外依据同源 DTM、正射影像、人工复核区以及数据缺测。 [USGS 火星互动地图](https://astrogeology-usgs.hub.arcgis.com/pages/interactive-maps-mars) · [Jezero SIM 3464](https://pubs.usgs.gov/publication/sim3464)
- **毅力号原始影像库**出现在站点卡和沿途照片。用 Sol 518 的单帧与标注图提供真实证据。按位置找图可先用 PDS Analyst’s Notebook，归档按产品 ID 和来源去重。需要量测、相机标定或立体像对时，再去 PDS 取匹配的科学级图像和 XML。已核对位置与姿态的照片才绘制拍摄点和视锥。 [原始影像](https://mars.nasa.gov/mars2020/multimedia/raw-images/) · [Analyst’s Notebook](https://an.rsl.wustl.edu/m20/) · [Mastcam-Z 团队的 PDS 获取说明](https://mastcamz.asu.edu/mastcam-z-data-for-all/) · [NASA 露头标注](https://science.nasa.gov/resource/two-perseverance-sampling-locations-in-jezeros-delta/)
- **好奇号 Mount Sharp 路线**提供信息组织示例。沿线加站名、科学目标、分段路径和俯视切换，借鉴它把地形、路径和目的连起来的方式。原片发生在 Gale，放在设计参考页并署名。 [NASA 路线动画与飞越](https://science.nasa.gov/resource/curiositys-proposed-path-up-mount-sharp/)
- **NASA Worldview**是地球遥感浏览器。借鉴同位置的图层透明度、对比滑杆、时间轴和图例信息。在我们的任务中，时间轴推进的是选定火星日的光照与任务位置。 [NASA Worldview](https://worldview.earthdata.nasa.gov/) · [NASA 软件目录](https://software.nasa.gov/software/GSC-17111-1) · [NASA Worldview 源码](https://github.com/nasa-gibs/worldview)

### 2.3 队友复现路径与系统缓存

1. **最快方式**。打开现有 `Jezero资源核验/derived` 使用已经取得的真实裁片。需要在线复取时，在资料目录的 Python 环境中运行既有的 `python crop_sources.py dtm ortho thermal`。现有脚本读取 `raw` 内已保存的 STAC 搜索结果并裁切，执行时会重写相应的 `*-native.tif`。在 QGIS 中也可以先用 USGS STAC 检索，再加载 COG 远程地址检查覆盖。 [USGS STAC 操作说明](https://stac.astrogeology.usgs.gov/docs/tutorials/basicpython/) · [QGIS 的 USGS ARD 工具](https://plugins.qgis.org/plugins/QGIS_ARD_Plugin/)
2. **新区域取数**。给定西、南、东、北四个火星经纬度以及采样/分析要求，STAC 返回覆盖候选和 `assets.*.href`。按覆盖、配套产品、网格尺度和质量标记挑选，按数据源投影读窗口。WMTS 读取 Capabilities 中的 `TileMatrixSet`、原点、范围和行列，路径顺序为 `Style/TileMatrixSet/TileMatrix/TileRow/TileCol`。火星等距圆柱矩阵和地球常见 XYZ 有不同定义。WMS/WMTS 颜色渲染、定量高程和 PDS 时间观测分别保留其原始格式与单位。若某新区只有区域级高程，继续提供概览，局部步行模式显示所需数据缺失。 [Mars Trek WMTS](https://trek.nasa.gov/tiles/apidoc/trekAPI.html?body=mars) · [GDAL 远程分块读取](https://gdal.org/en/stable/user/virtual_file_systems.html)
3. **先验数据包，再切换版本**。联网的准备命令获取并核验格式、投影、覆盖、NoData 和哈希。缓存键含产品与版本、范围、投影、输出网格和时间。下载或转换失败时保留最近一次成功版本，区分「无覆盖」「文件未完整读取」和「服务暂不可用」。整图原档、缓存和资料 PDF 留在准备环境。应用发布固定的小包，包内清单记录源 URL、仪器、产品 ID、日期或 Sol、分辨率、单位、处理过程和署名。

**手动试一次调用**。在 PowerShell 中执行以下命令只读取两个小型 JSON 响应。已验证第一个返回两项立体地形候选和各自的资源 URL。第二个返回示例范围内相交的八个 SIM 3464 地质单元要素，包络单位为服务原生投影的米，结果可进一步裁切。最终计算读取第一条返回的高程 TIFF 窗口，并利用第二条返回的属性作科学解释。 [USGS STAC 教程](https://stac.astrogeology.usgs.gov/docs/tutorials/basicpython/) · [SIM 3464 服务图层 8](https://services.arcgis.com/v01gqwM5QqNysAAi/arcgis/rest/services/Jezero_FeatureServiceFromPro/FeatureServer/8)

```powershell
curl.exe -fSL 'https://stac.astrogeology.usgs.gov/api/search?collections=mro_hirise_socet_dtms&bbox=77.401%2C18.454%2C77.411%2C18.464&limit=20' -o jezero-stac.json
curl.exe -fSL 'https://services.arcgis.com/v01gqwM5QqNysAAi/arcgis/rest/services/Jezero_FeatureServiceFromPro/FeatureServer/8/query?where=1%3D1&geometry=-6400%2C1092900%2C-4100%2C1095400&geometryType=esriGeometryEnvelope&spatialRel=esriSpatialRelIntersects&outFields=OBJECTID%2Cunit%2Cname&returnGeometry=true&f=json' -o jezero-geology.json
```

## 3. 精细坐标与环境因素

### 3.1 局部影像配准

本次把 Mars Trek 的受控拼图瓦片和已取 DTM 的配套正射图重投影到同一 1 m 分析网格，对六处 80 × 80 m 图像窗口进行相关匹配。以配套正射图为基准，Mars Trek 瓦片的同一特征偏西约 23–24 m、偏北约 20–22 m，合计约 **31–33 m**。这组数值只描述本地两种产品的相对偏差。另从 TRN DTM 读取 Swift Run、Hazeltop 和区域中心三个像元，与原立体 DTM 对应像元约差 8.5–11.1 m。垂直基准、水平偏移与坡度影响尚未分清。 [USGS TRN DTM](https://www.usgs.gov/data/mars-2020-terrain-relative-navigation-hirise-dtm-mosaic) · [USGS 对 Jezero 立体 DTM 的质量评估](https://www.usgs.gov/publications/evaluating-stereo-dtm-quality-jezero-crater-mars-hrsc-ctx-and-hirise-images)

先采用已拿到的**同立体产品正射图和 DTM**作局部计算组合。Mars Trek 保留在区域视图和来源对照视图。再按以下顺序确认局部发布基准。

1. 固定经度向东、纬度类型、火星半径和每个源产品的 WKT/垂直基准。已裁源范围是东经 77.401–77.411°、北纬 18.454–18.464°。以 `77.406°E, 18.4588°N` 为中心、3,396,190 m 球面半径的本地方位等距投影构建米制网格。任务范围东、北各 ±260 m，2 m 网格共 260 × 260 格。向外另按遮挡和边界计算需求取缓冲区。
2. 在轨道影像之间选取分布均匀的同名地物，留一部分地物独立检验拟合误差。用 TRN 同版正射/高程核对，并查 PDS PLACES 与任务文档确认采样记录坐标对应的实物和参考框架。精细影像叠加可先把一到两格，即 2–4 m，相对残差作为演示目标，发布时报告实际误差，独立站点定位另做核验。精度不足时扩大不确定区域，在证据视图展示历史位置，并选择位置与视线已核验的模拟观察站。记录原始 NASA 坐标和通过验证的变换参数。 [PDS 位置与姿态档案](https://pds-geosciences.wustl.edu/missions/mars2020/places.htm) · [TRN 配套正射影像](https://astrogeology.usgs.gov/search/map/Mars/Mars2020/JEZ_hirise_soc_006_orthoMosaic_25cm_Eqc_latTs0_lon0_first)
3. 高程与正射用有依据的重采样方法，分类和缺测掩膜用最近邻或更保守的合并。2 m 图先寻路，再用约 1 m 源 DTM 与正射复核窄脊、沟槽、边界和可疑岩块。计算路线距离、坡度、相对高差时使用同一 DTM。影像像元间距、高程网格间距和定位精度分别记录。交换火星矢量优先用带 CRS 的 GeoPackage，网页也可用明确写出火星 CRS 的内部 JSON。 [HiRISE ARD 数据说明](https://stac.astrogeology.usgs.gov/docs/data/mars/hirise_dtms/) · [GeoJSON 标准的坐标约定](https://datatracker.ietf.org/doc/rfc7946/#section-4)

## 4. 多目标规划与自动重规划

### 4.1 输入、硬约束和度量

每次规划读取起点、当前位置、已访问站点、站点优先级与停留时长、出发时刻、总预算、返航预留、数据包版本及环境或封路情景。每次结果保存参数、地图版本和代价模型版本，支持同场景复现。选中一条候选线就能查各段时间与具体折衷。时间预算是首版的资源指标。以后接入电量、供氧或负载影响时，按各自的设备参数、单位和测试数据建立约束。

1. **生成有向地形图**。2 m 格网最多 67,600 个格，保留有效且在模拟坡度限制内的连边。每步由平面距离和高差求方向坡度，必要时计算地表路径长和横坡。八邻域的对角边只有在两侧相邻格均可走且整条边不穿过阻断掩膜时才通过。按已审核的障碍、定位误差和覆盖边界生成通行掩膜。点击障碍或无数据时要求重新选择合法点。自动吸附仅在指定容差内进行，界面显示吸附位移。
2. **定义目标**。先比较总用时、地形暴露和低光暴露，另显示路线长度、爬升、最大坡度、返航预留和完成的科学站。地形暴露可用高坡度路段的米数，粗糙度加入时保留独立指标和窗口尺度。若只做静态试算，可用固定的保守步速。后续根据有根据的坡向、负载和地表速度模型估时。科学价值在满足站点任务时计一次，去回重合的路段仍各计一次实际时间。
3. **算清返航**。`可用余量 = 总预算 − 已用时间 − 未来行走时间 − 未来科学停留 − 返航预留`。未来行走时间包含返航段。对外显示预计返回时刻和扣预留后的余量。预算不足时显示超出多少，返航本身也超预算时保留最短预计返航时间及偏差，并明确标记。

| 提供给使用者的候选 | 搜索和比较的口径 |
|---|---|
| 优先节省时间 | 用非负步行时间做代价，覆盖同样的站点要求并返回基地。展示与其他路线相差的时间和爬升。 |
| 优先减少陡坡暴露 | 给陡坡/粗糙路段更高代价，或限定允许的暴露上限再找较快的线。硬性坡度上限对所有方案都适用。 |
| 优先减少低光暴露 | 在太阳角和遮挡计算通过核验后启用。按预计通过时刻计算阴影/低光分钟，并展示未知时段。若不同走廊间差别很小，直接显示该时段的结果。 |
| 完成更多科学目标 | 两站允许顺序变更时尝试「基地→A→B→基地」与反序。预算内两站方案不足时按优先级显示可行的单站任务。单站属于任务调整，界面显示放弃哪项观察、节省多少时间。 |

### 4.2 搜索方法和动态情景

- **首版搜索**。复用现有 A*/Dijkstra 的搜索框架，把当前对称的栅格代价扩展为含行进方向与阻断检查的边代价。对同一站点组合，用多组固定权重生成候选。边代价用 `时间权重 × 标准化耗时 + 地形权重 × 标准化陡坡距离 + 光照权重 × 标准化低光时间`，各项单位和归一化基准固定。每条候选重新检查所有边、站点和总预算。A* 的估值取直线距离乘每米代价的下界，用小图 Dijkstra 对照。硬约束保证路径在当前模型下可行，软权重表达用户偏好。现有 `evaluate_eva_route` 能评估给定路径，闭环返航、站点停留和模拟资源字段需要按本场景扩展或重新标定。 [现有网格搜索](https://github.com/cassius0848/mars-pathfinder-ai/blob/1e4092304981417b57e2111c8d55f2182d2435e3/src/mars_pathfinder/routing/search.py) · [现有任务评估](https://github.com/cassius0848/mars-pathfinder-ai/blob/1e4092304981417b57e2111c8d55f2182d2435e3/src/mars_pathfinder/analysis/mission.py)
- **给出真正不同的选择**。如果多组权重集中在同一条线，可为已经选中的走廊加一个临时搜索惩罚，再找一条候选，用原始指标复算其代价。在完成相同任务的候选中删去各目标都不更好且至少一项更差的路线。合并重复路径和实际差异很小的路径，比较走廊重叠率与可见指标差。界面可显示「多走 X 米，少通过 Y 米陡坡」这样的具体取舍。加权搜索覆盖的是生成的候选集，结果数量取决于可用走廊，可能只有一条，或当前条件下找不到可行路线。
- **处理时变照明**。首版准备少量出发窗口。为不同照明时间片生成候选，沿完整路线逐段推进预计时刻，加入科学停留，再用对应时刻的阴影格网复算。用复算后的暴露与返航结果排序。报告低光已知分钟和未知分钟，未知比例妨碍比较时停用该情景的低光排序。需要更精细的时变搜索时，再把 `位置 + 时间桶 + 已访问站点` 一起作为状态，验证时间步长敏感性与运行开销。
- **执行视图自动重规划**。用户沿规划路线回放，或手动给定当前位置、剩余时间和封路。保留已完成的站点和已耗时，更新当前图，只重算未来路线与直接返航。无路时显示断开的区域或限制原因。演示规划位置来自回放或手动输入。火星上的真实定位需要视觉、惯导或其他任务定位系统，手机地球定位接口不能给出火星位置。 [JPL 毅力号火星定位](https://www.nasa.gov/missions/mars-2020-perseverance/perseverance-rover/nasas-perseverance-now-autonomously-pinpoints-its-location-on-mars/)

### 4.3 现有试算能验证什么

已有真地形试算，在 **15 m/min 恒定步速、每站 12 min、8 min 返航预留、18° 模拟地表坡度阈值**下，两站最短和坡度加权分别为 **582.7 m / 17.66°** 与 **616.9 m / 16.81°**，两者在 80 min 时都有预留后的余量。55 min 时，旧脚本的 Hazeltop 单站方案有约 2.0 min 余量，Swift Run 单站超约 3.4 min。数值来自旧坐标组合和静态模型，只供说明计算量级与预算互动。加入配准复核、障碍、角点检查、行进坡度和光照后必须重算，再用新结果选择演示预算。

## 5. 二维地图、三维模型和实时计算

**二维地图可以直接做**。主地图用局部东、北米制坐标，同尺度绘制正射影像、路线、去回方向箭头、数据覆盖和科学站。地图与沿途高程剖面联动，图层支持坡度、阴影、地质、热红外区域视图以及历史火星车轨迹。地质与热红外有各自的比例尺或像元间距。把通过约束的路段、尚需人工复核的区域、封路和未知用线型及图例区分。路线卡保留预计时间、站点与停留、返航余量和数据版本。

**三维模型可从已经取得的高程直接建立**。每格有 `东向米、北向米、高程米`，可组成高度网格或三角网，再叠配套正射或坡度色带。2 m 网格约 6.76 万个顶点，最多约 13.4 万个三角面。可以另做约 130 × 130 的低精度显示网格，保留 2 m 网格用于规划，检查显示简化导致的线面偏差。三维路线高程从渲染所用表面采样，并用源 DTM 复核。首版用 Plotly 的 3D Surface 或 Mesh3d，默认真实垂直比例，可旋转、复位俯视、选择同一路线。只在全彩贴图或连续飞越对展示有明显价值时，升级到 Three.js/glTF。 [Plotly 三维地形](https://plotly.com/python/3d-surface-plots/) · [USGS HiRISE 立体产品](https://stac.astrogeology.usgs.gov/docs/data/mars/hirise_dtms/)

**需要即时的是交互和重算**。影像重投影、派生栅格、地形网格和少量太阳角时间片提前准备。旋转时由浏览器渲染，修改出发时间、预算、当前位置或封路后由本地路由器计算。普通单张光学影像没有唯一可恢复的高程。如果未来要做站点级近景三维，可以按 PDS 获取匹配的左右目图像、相机模型和姿态，先离线做立体重建，再尝试与轨道 DTM 对齐。视觉模型可以辅助标记疑似岩块或沙地，需要地面或轨道影像各自的标签与独立验证。NASA AI4MARS 主要是地面车载相机的地形标签，应用于轨道影像或穿宇航服步行要另做验证。首版的实际三维几何由官方立体 DTM 提供。 [Mastcam-Z 科学级影像说明](https://mastcamz.asu.edu/mastcam-z-data-for-all/) · [NASA AI4MARS](https://data.nasa.gov/dataset/ai4mars-a-dataset-for-terrain-aware-autonomous-driving-on-mars)

|---|---|---|
| 途中自动优化路线 | 封路、位置、停留时间或预算更新后重算未来路线。把原结果和新结果的原因与影响同时展示。 | 首版。纯本地算法，无需模型密钥。 |
| 学习个人/团队偏好 | 允许用户确认是否保留路线偏好。以本地 JSON 或 SQLite 存储选择与当时的路线指标，按反馈微调软权重，也能重置。硬性坡度、封路与返航规则来自已确认的任务配置。 | 可以先记录、回放和手动调整。自动更新软权重需要先验证反馈样本。 |
| 学习步行或避障代价 | 记录可对齐到路段的实际或类比测试耗时、坡向、负载、地表类型、时间与数据来源。积累数据后可用可解释回归拟合速度或耗时，按任务、人员和区域分组做留出验证，输出误差和保守区间。对比基线的时间偏差与错误通过预算的次数。验证通过后以版本发布，保留旧版本和回放结果。 | 后续。有明确地面测试、类比和仿真标签，才谈模型性能改善。仿真反馈可验证算法逻辑，真实步行结论需要相应测量。 |
| 用自然语言发指令或解释 | 如果以后加入 LLM，把任务输入变成受校验的字段，只给模型已算好的路线指标、来源和限制。路线由本地搜索生成，说明也可用模板。在线模型密钥放服务端。 | 可选。首版的取数、寻路、重规划、三维和学习记录都无需调用生成式 AI API。 |

## 8. 实施顺序、队伍准备和验收

| 顺序 | 完成内容 | 验收时看什么 |
|---|---|---|
| A · 数据与定位 | 固定 Jezero 数据包版本，输出来源清单、同源影像高程、地质与热红外，确认采样点坐标链，复核基地、观察站与可走廊道。 | 同一控制点在源图和本地地图间可往返转换。局部产品对齐有保留点残差。独立数据误差较大时按不确定性处理。检查单位、覆盖和 1 m/2 m 地形敏感性。 |
| B · 端到端二维任务 | 基于现有仓库新增闭环任务和候选比较。显示路线、剖面、证据卡、预算与返航按钮，并用现场封路事件触发重规划。 | 路径每步都可验证，拒绝无效端点和角点穿越。两站、单站和直接返航有同场景可回放示例。旧试算重做，按实测比较结果选演示参数。 |
| C · 光照、三维和导出 | 生成两个经核对的太阳/照明场景和同源三维。沿路线推进时钟，显示光照、当前段和返航余量。导出一页任务卡与自包含 HTML。 | 用已知遮挡案例检查算法和缺测处理，抽样对比 Trek 的太阳角。二维/三维站点、航向与剖面对应。若光照尚未验收，展示已完成的环境层并标注照明缺失，路线比较保留时间和地形。 |
| D · 离线发布与彩排 | 准备固定数据包的评委网页、本地启动说明、数据来源和任务视频。笔记本、平板浏览器分别实测。 | 断开外网后完成一轮规划、变更条件、重规划、看照片/3D 和导出。用未登录浏览器打开评委网址。记录首屏与重规划时间。可把当前测试机热启动重规划不超过约 2 秒作为性能目标，结果以实际测量为准。 |

**团队需要准备**。一份可运行仓库快照、固定的 Python 环境和依赖、当前 Jezero 小裁片及来源清单、一台用于离线彩排的笔记本，以及可安排的网页托管环境。已有栈包含 NumPy、SciPy、Rasterio、PyProj、Streamlit 与 Plotly。小区域的寻路可用常规 CPU，三维渲染依靠浏览器 WebGL。数据同学负责投影、来源和科学点，规划同学负责指标和返航校验，界面同学负责地图、执行回放和发布，按队伍人数合并角色。对本次验证过的公开数据请求未用专用 API 密钥。 [现有网页入口](https://github.com/cassius0848/mars-pathfinder-ai/blob/1e4092304981417b57e2111c8d55f2182d2435e3/app/streamlit_app.py) · [仓库依赖清单](https://github.com/cassius0848/mars-pathfinder-ai/blob/1e4092304981417b57e2111c8d55f2182d2435e3/requirements.txt)

**两天工作节奏**。开赛后第一天先并行验收数据、把局部高程接进现有页面，并用单站往返贯通数据、搜索、剖面和站点证据。第一天结束前完成两站候选与返航预算。第二天先完成封路重规划、光照和三维，留出发布、断网复测、录制和整理来源的时间。若地形或站点定位有问题，先收紧可用范围并复核，再决定候选数量。若性能或时间受限，保留二维主流程和可旋转的简化地形。

**比赛演示顺序**。从 Mars Trek 区域图定位到 Jezero 三角洲，进入局部正射图。打开 Swift Run 与 Hazeltop 的站点证据，比较时间优先与地形优先路线。若光照场景通过核验，再改变出发时段，检查阴影暴露与路线差异。随后缩短预算或报告封路，从途中位置重算。最后打开同一条路线的 3D、查看返航余量并导出任务卡。交付包含源码和启动说明、固定版本的数据包与逐项署名、网页链接、离线演示文件和验收记录。

**建议你确认的范围**。沿用 Jezero/Hawksbill Gap 和双科学站。比赛版交付二维导航、多目标比较、环境条件与预算驱动的重规划、同源轻量三维、一个评委网址和一套本地离线包。持续学习先保留记录和参数接口，待有测量后做模型校准。如果要求平板完全独立离线，需额外实现 PWA 端内的寻路和数据存储。当前为研究与方案审阅阶段。
