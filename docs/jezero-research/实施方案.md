# Mars Pathfinder AI · Hawksbill Gap 火星出舱任务实施方案

在 Jezero 西部三角洲做一个约 **520 × 520 米**的交互式任务区。两名宇航员从模拟基地出发，比较 Skinner Ridge 的 Swift Run 砂岩与 Wildcat Ridge 的 Hazeltop 含硫酸盐细粒沉积岩，随后返回。作品用同一张地图回答三件事：为什么去、从哪里走、时间缩短后还能完成哪项科学任务。

方案依据用户提供的官方 Details 和五条 Resources。题目要求整合多个 NASA 科学任务的数据，服务人类火星表面探索和沿途科学。题面建议至少三种数据。此方案使用 MRO 的地形和光学、Mars Odyssey 的热红外、Mars 2020 毅力号的地面影像与现场科学记录，辅以 USGS 地质图。题面允许静态条件或历史观测，首版专注地形和地质。官方 Resources 中的 Mars Trek 底图和毅力号影像在作品里实际展示并注明出处。 [Details](https://www.spaceappschallenge.org/2026/challenges/interplanetary-survival-guide-martian-map/?tab=details) · [Resources](https://www.spaceappschallenge.org/2026/challenges/interplanetary-survival-guide-martian-map/?tab=resources) · [组委会答复](https://github.com/nasa/spaceapps/discussions/1827)

## 1. 初步搭建与数据接口

以 [当前 GitHub 快照 `1e40923`](https://github.com/cassius0848/mars-pathfinder-ai/tree/1e4092304981417b57e2111c8d55f2182d2435e3) 为参考。它已接入真实的 MOLA 高程、Viking 光学样例和 SIM 3464 地质资料，能绘制地形和单程路线。MOLA 原样例的导出范围为 1° × 1°、256 × 256，在此区域是每像元约 220–230 米的采样量级。把该模式保留作区域概览。发布的 Hawksbill Gap 模式使用本次 HiRISE 裁片。仓库现有 Sol 1934 影像是图库样例，Hawksbill Gap 的证据卡换成可追溯到 Sol 518 和采样记录的内容。

使用 Python 3.11+、NumPy、SciPy、Rasterio、PyProj、Shapely、Streamlit 和 Plotly。复用 `src/mars_pathfinder` 的模型与路由接口。新增独立数据准备入口，避免页面刷新时重新下载。运行约定建议为 `python -m pip install -r requirements.txt`、`python -m pytest` 和 `python -m streamlit run app/streamlit_app.py`，并用项目配置统一 `src` 导入。项目目录分工如下。

| 模块 | 应实现的接口和文件 |
|---|---|
| `scripts/` | 数据获取与准备命令，支持本地缓存、固定 STAC 产品、重跑裁片和输出完整性检查。 |
| `data/processed/hawksbill_gap/` | `dem_2m.tif`、`slope_2m.tif`、`hazards.gpkg`、`geology.gpkg`、`science_sites.gpkg`、正射底图、热红外背景、精选照片和 `manifest.json`。将大原图留在本地缓存。 |
| `src/mars_pathfinder/data/` | 读入数值、掩膜、仿射变换、CRS、数据 ID、单位与原始分辨率。通过仿射变换做坐标与行列号转换。 |
| `routing/` 与 `analysis/` | 按约束生成各段路径，拼接完整任务，计算与复核每段和全程预算，给出两站、单站或返回的可行选项。 |
| `app/` | 区域定位图、主任务图、路线剖面、站点证据、预算交互和任务卡。 |

数据清单每项至少写入 `product_id`、任务/仪器、资源入口、原文件/服务 URL、版本、拍摄日期或 Sol、空间范围、CRS WKT、单位、原始分辨率、实际输出网格、缺测值、处理步骤、署名和 SHA-256。界面用「观测」「派生」「模拟」标识数据属性。显示用 TIFF 及路径导出记录火星坐标；需要交换空间数据时优先 GeoPackage，保留自定义火星 CRS。网页内部也可用带火星 CRS 元数据的 JSON。RFC 7946 GeoJSON 的标准 CRS 为地球 WGS 84。 [RFC 7946](https://datatracker.ietf.org/doc/rfc7946/)

## 2. 投影、分辨率和科学证据

1. 先取得东经 77.401–77.411°、北纬 18.454–18.464° 的高分辨率源裁片。以东经 77.406°、北纬 18.4588° 为中心，在半径 3,396,190 m 的火星球面上用本地方位等距投影建立米制坐标。局部分析窗口为东、北各 ±260 m，`260 × 260` 个 2 m 格。影像显示保留更细的采样，禁止用影像分辨率冒充高程精度。SIM 3464 以原生火星 WKT 获取并变换，避免把火星要素送入地球底图或地球坐标变换。
2. 源 DTM 缺测与数据边界保持不可通行。用 2 m 网格的高程梯度计算坡度，另保留原始 DTM 复核窄脊、沟槽和强坡变化。对分类掩膜使用最近邻。热红外保持 100 m 解释尺度，并在区域位置图单独呈现。发布前在任务区内选至少三个可辨地貌对照点，核对 Mars Trek 底图和计算用 DTM/正射的横向配准，记录误差。当前裁片尚未完成现场尺度横向配准验收。若比较 PDS 报告高程与 DTM，先核对垂直基准、取点方法与局部坡度；本次从栅格抽出的标高和报告值约差 8.6–10.7 m，暂以同一 DTM 计算相对高差。
3. 将真实采样点和模拟观察点分别建模。Swift Run 坐标为 `77.40617078°E, 18.458931°N`，Hazeltop 为 `77.40588851°E, 18.45863707°N`。科学卡为 A 提供砂岩层理、颗粒和样品背景，为 B 提供细粒沉积、含硫酸盐脉体和原始记录。标注照片拍摄点与目标方位，方位未核实时只把照片作为站点证据。用地图核查观察点与崖缘的距离和可视范围，再将通过复核的位置用于正式演示。 [NASA PDS](https://pds-geosciences.wustl.edu/missions/mars2020/Mars%202020%20Initial%20Reports%20Volume%202%20Release%202.pdf) · [任务区地层研究](https://doi.org/10.1029/2023JE008187)

## 3. 规划与任务判断

硬约束包括数据边界、缺测、模拟坡度上限和影像复核后人工标出的禁行区。八邻域寻路禁止从两个相邻不可通行格之间对角穿越，也检查相邻像元间坡度。已有 Dijkstra 验证固定站序。正式版可用仓库的 A*，以直线距离乘最小单位代价作启发值，并用 Dijkstra 检验小图的结果。比较同样约束下的最短路线与坡度加权路线。坡度方案的分段代价为 `距离 × [1 + 4 × (两端最大坡度 / 18°)²]`，权重与 18° 上限均为演示参数。正式图标明人工核验障碍和由坡度计算得到的禁行范围；岩块、沙地和崖缘附近的可通行性按影像及不确定性单独审阅。

逐段计算基地→A、A→B、B→基地。每段保存距离、起终点、坡度分布和用时。全程预算为行走用时加两站停留，最后扣除预留。第一版只做时间预算，演示步速 15 m/min、每站 12 min、返航预留 8 min，任务时间可交互调整。两站超时，按优先级试单站往返。行进视图根据模拟当前位置计算直接返航耗时和预留。显示应写「通过模拟时间预算」或「超出模拟预算」，并给出超出的分钟数。

## 4. 最终可视化与演示

- 主页面采用 Streamlit + Plotly 局部米制地图，横纵同比例。默认打开 Mars Trek 光学底图、路线和科学站；可叠加坡度、禁行范围、地质边界，支持透明度和同步对照。用颜色与线型同时区分去程、返程和备选方案。区域窗口展示 THEMIS，显示当前 EVA 范围与热红外的原始尺度。
- 选择 A 或 B 后，侧栏显示真实照片、科学观察任务、来源和模拟停留时长。下方显示以累计距离为横轴的高程剖面，标出停留点和陡坡段；沿线卡片同步更新当前路段、下一个路标和预计返航余量。用 2D 地图完成首版验收，3D 仅作为后续展示增强。
- 演示从 80 分钟开始，显示两条可达路线并点击 A/B 查科学证据。把预算改为 55 分钟，让地图自动高亮 Hazeltop 单站往返，并显示剩余约 2 分钟。随后导出一页任务卡，包含路线、距离、坡度、停留、返航预留、数据来源和模拟条件。终稿展示文案使用实际重新计算结果，人工障碍加入后重新选择演示预算。
- 公开可运行演示和任务区离线数据包。来源页列出图层 ID、Sol、图像署名和原始链接。提交前用无登录窗口验证评委可访问演示和所需附件，并按 2026 提交指南核对格式。 [赛事主页](https://www.spaceappschallenge.org/2026/) · [官方提交指南入口](https://www.spaceappschallenge.org/resources/)
